# Бит.Serves — микросервисная платформа

Единая среда инструментов отдела продаж: расчёт заработной платы, дашборды руководителя, конструктор коммерческих предложений. Приложение для пользователя — монолит (одна витрина, один вход), внутри — независимые сервисы, каждый в своём контуре со своей базой данных.

## Архитектура

```
                        ┌──────────────────────────┐
 Браузер (SPA)  ──────► │  Gateway (nginx / local) │
                        └───────────┬──────────────┘
             /api/auth/*, /api/departments, /api/grades, /api/positions, /api/admin/*
                                    │
              ┌─────────────────────┼──────────────────────┬──────────────────┬─────────────────┐
              ▼                     ▼                      ▼                  ▼                 ▼
      ┌──────────────┐     ┌──────────────┐       ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
      │ auth-service │     │payroll-service│      │dashboard-svc │   │  kp-service  │   │funnel-service│
      │    :8001     │◄────│    :8002     │◄──────│    :8003     │   │    :8004     │   │    :8005     │
      └──────┬───────┘     └──────┬───────┘       └──────┬───────┘   └──────┬───────┘   └──────────────┘
             │                    │                      │                  │             (без БД —
         auth_db              payroll_db          (без своей БД —       kp_db              статика,
      (пользователи,       (расчёты ЗП,           агрегирует данные   (документы КП)      localStorage
       справочники,         себестоимость)         auth + payroll)                         в браузере)
       грейды, аудит)
```

- **auth-service (8001)** — регистрация/вход (JWT), справочники (отделы, должности, грейды со ступенями плана и KPI 2), администрирование пользователей и грейдов, аудит входов, сброс пароля по коду. Отдаёт другим сервисам профили пользователей через защищённый internal API (`/internal/*`, заголовок `X-Internal-Token`).
- **payroll-service (8002)** — расчёт ЗП по марже и грейду (ступени выполнения плана, KPI 2 за сохранность клиентов), история и сводка по месяцам, выгрузка расчёта в Excel, учёт себестоимости продаж.
- **dashboard-service (8003)** — контур руководителя: дашборд отдела, аналитика по месяцам, тепловая карта, водопад маржи, рентабельность, расходы отдела (ФОТ, НДФЛ, взносы, НДС, офис). Свой БД нет — агрегирует данные auth-service и payroll-service по internal API. Доступ только с ролью `head`.
- **kp-service (8004)** — конструктор коммерческих предложений: хранение документов КП по пользователям, автосохранение из фронтенда, копирование КП, публикация в общее пространство (все пользователи видят расшаренные КП, чужие — только просмотр), справка по функционалу. Доступен всем ролям.
- **funnel-service (8005)** — воронка продаж «Промышленная маркировка»: самодостаточный статический дашборд (сделки, этапы, аналитика). Своей БД нет — данные хранятся в браузере пользователя (localStorage), резервная копия — экспортом/импортом из дашборда. Открывается по адресу `/funnel/`.
- **frontend/** — статический SPA-монолит (`index.html`, `app.js`, `styles.css`) + конструктор КП (`kp.html`).
- **nginx/** — production-шлюз: отдаёт статику и проксирует `/api/*` в сервисы.

Каждый сервис — отдельный контур: свой процесс/контейнер, своя БД, свой `Dockerfile`. Межсервисные вызовы — только по HTTP через internal API с токеном.

## Быстрый старт (локально, без Docker)

Требования: Python 3.12+ с пакетами из `requirements.txt` сервисов (fastapi, uvicorn, sqlalchemy, httpx, python-jose, bcrypt, openpyxl, pydantic-settings, pydantic[email]).

```bash
# из корня репозитория
python local_launcher.py            # или: npm run dev
```

Windows: можно просто запустить **`start.bat`** двойным кликом. Остановка — **`stop.bat`** (гасит все процессы на портах 8000–8004) или Ctrl+C в окне лаунчера.

После старта: **http://localhost:8000**

Локальный запуск использует SQLite в `./dev_data/` (по одному .db на сервис) и не требует PostgreSQL. Порты сервисов: 8001–8005, шлюз — 8000 (можно переопределить: `python local_launcher.py --port 8080` или переменной `PORT`).

При первом старте auth-service сеет справочники: отделы (Развитие АРТ, Сопровождение, АБТ), должности и грейды. Для отдела АРТ: Испытательный срок, Менеджер 1–2 грейд, Ведущий менеджер 1–2 грейд (ступени плана). Для отдела АБТ: Испытательный срок и Менеджер отдела Сопровождения (схема мотивации СБИС).

## Отдел АБТ (мотивация СБИС)

Отдел АБТ работает по собственной системе мотивации (`scheme="abt"` у грейда). Условия мотивации видны только этому отделу: грейды привязаны к отделу (`department_id`), при регистрации и в профиле список грейдов фильтруется по отделу пользователя, сервер валидирует соответствие.

**Ввод:** период, отработанные/рабочие дни, НДФЛ и реализация по 5 типам продаж — новые продажи, расширение, апгрейд, продление без изменений, товары СБИС.

**Ставки от выполнения нормы реализации ДС** (норма = план грейда; выполнение = (новые + расширение + апгрейд + продление) / норма):

| Тип продажи | 0–89,99% | 90–99,99% | 100–109,99% |
|---|---|---|---|
| Новые продажи | 8% | 10% | 13% |
| Расширение | 7% | 9% | 11% |
| Апгрейд | 5% | 7% | 9% |
| Продление без изменений | 1,2% | 1,3% | 1,5% |
| Товары СБИС | 10% всегда | | |

При перевыполнении (≥110%) меняется только ставка «новых продаж»: 110–119,99% → 15%, 120–129,99% → 17%, ≥130% → 20%; типы 2–4 остаются на ставках колонки 100–109,99%.

**KPI 2 (АБТ):** фиксированная премия 5 000 ₽ при сохранности клиентов ≥ 83% (`kpi2_bonus_type="fixed"`).

Дашборды руководителя АБТ работают по аналогии с АРТ: в качестве «маржи» используется сумма реализации по всем типам продаж.

## Запуск в Docker (production-контур)

```bash
cp .env.example .env     # при необходимости поменять секреты
docker compose up --build
```

Поднимаются: 3 PostgreSQL (по одной на сервис с БД), 5 сервисов, nginx-шлюз на порту 80.

## Учётные записи и роли

- **Менеджер** (`manager`) — расчёт ЗП (отделы «Развитие АРТ» и «АБТ», у каждого своя мотивация), история, Excel, конструктор КП, профиль.
- **Руководитель** (`head`) — всё, что у менеджера, плюс: дашборд отдела, аналитика, рентабельность, расходы, управление грейдами и пользователями.

Регистрация руководителя требует пароль подтверждения — переменная `HEAD_REGISTER_PASSWORD` (по умолчанию `123456789`, **обязательно смените в production**).

### Восстановление пароля по почте

Форма «Забыли пароль?» генерирует 6-значный код (TTL — `PASSWORD_RESET_CODE_TTL_MINUTES`, по умолчанию 15 мин). Доставка кода:

- **SMTP настроен** (`SMTP_HOST` и остальные `SMTP_*` заданы) — код приходит письмом на почту пользователя (HTML + текстовая версия). Если письмо не ушло (SMTP недоступен, неверные креды) — API вернёт 503, код не засвечивается.
- **SMTP не настроен** (по умолчанию) — dev-режим: код печатается в консоль auth-сервиса.

Настройка в `.env` (см. `.env.example`): для Яндекс.Почты — `smtp.yandex.ru:465`, `SMTP_USE_SSL=true`, в `SMTP_PASSWORD` указывается **пароль приложения** (создаётся в настройках аккаунта), не основной. Для Gmail — `smtp.gmail.com:587`, `SMTP_USE_SSL=false` (STARTTLS). Для корпоративной почты — хост/порт у системного администратора.

## Переменные окружения

См. `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | подпись JWT (единая для всех сервисов) |
| `INTERNAL_API_TOKEN` | токен межсервисных вызовов `/internal/*` |
| `HEAD_REGISTER_PASSWORD` | пароль регистрации руководителя |
| `AUTH_SERVICE_URL` / `PAYROLL_SERVICE_URL` | адреса сервисов для межсервисных вызовов |
| `VAT_RATE_PERCENT`, `INSURANCE_RATE_PERCENT`, `NDFL_RATE_PERCENT`, `OFFICE_COST_PER_EMPLOYEE` | экономика расчётов (НДС, взносы, НДФЛ, офис на сотрудника) |
| `POSTGRES_*` | подключения к БД (в Docker) |
| `DATABASE_URL_OVERRIDE` / `DATABASE_URL` | переопределение DSN (локально — SQLite) |

## API (кратко)

- `POST /api/auth/register`, `POST /api/auth/login` — выдача JWT; в `user` возвращается полный объект `grade` (план, ступени, KPI 2).
- `GET/PUT /api/auth/me` — профиль; `POST /api/auth/forgot-password|verify-reset-code|reset-password` — сброс пароля.
- `GET /api/departments|positions|grades` — публичные справочники.
- `POST /api/payroll/calculate`, `GET /api/payroll/history|summary|cost-price`, `POST /api/payroll/cost-price`, `GET /api/payroll/records/{id}/export` — расчёты ЗП.
- `GET /api/head/dashboard|history|waterfall|costs`, `POST /api/head/profitability` — контур руководителя (роль `head`).
- `GET/POST /api/admin/grades`, `PUT/DELETE /api/admin/grades/{id}`, `POST /api/admin/grades/{id}/restore`, `GET /api/admin/users`, `PUT /api/admin/users/{id}/grade|position`, `DELETE /api/admin/users/{id}`, `POST /api/admin/users/{id}/restore|reset-password` — администрирование (роль `head`).
- `GET/POST /api/kp/documents`, `GET/PUT/DELETE /api/kp/documents/{id}` — документы КП (все роли, изменение — только свои).
- `GET /api/kp/documents/shared` — общее пространство КП (расшаренные всеми пользователями).
- `POST /api/kp/documents/{id}/copy` — копия документа (своего или из общего пространства).
- `POST /api/kp/documents/{id}/share|unshare` — публикация/снятие из общего пространства (только владелец).
- `GET /internal/users/{id}/profile`, `GET /internal/departments/{id}/members` — internal API (только с `X-Internal-Token`).

## Логика расчёта ЗП

### Отдел АРТ (схема «маржа»)

- Все суммы вводятся уже без НДС — сервис ничего не вычитает, расчёт идёт напрямую от введённых значений.
- Маржа для плана = маржа услуг + маржа товара.
- Грейд с планом: % премии определяется ступенью выполнения плана (tiers), например 90% → 4%, 130% → 6%. Ниже первой ступени — 0%.
- Грейд без плана (Испытательный срок): фиксированный % от маржи.
- Премия за услуги = маржа услуг × коэф. услуг × % ; премия за товар = маржа товара × %.
- KPI 2 (если включён в грейде): приход × %, выплачивается при сохранности клиентов ≥ порога (приход тоже без НДС).
- KPI 3 «продажа новых АС»: премия 5% от суммы прихода с АС (без НДС), начисляется всегда.
- Gross = оклад пропорционально дням + премии + KPI 2 + KPI 3; Net = Gross − НДФЛ.

### Отдел АБТ (схема «abt»)

- Премия = Σ (реализация по типу × ставка колонки выполнения нормы) + товары СБИС × 10%.
- Колонка ставок определяется % выполнения нормы реализации ДС (см. таблицу выше); грейд без плана — базовая колонка 8/7/5/1,2%.
- KPI 2: фиксированные 5 000 ₽ при сохранности ≥ 83%.
- Gross/Net — как в АРТ. Оклад по умолчанию 40 000 ₽.

Smoke-тесты: `services/payroll/test_abt_calc.py` (схема АБТ) и `services/payroll/test_kpi3_smoke.py` (KPI 3) — запуск: `python test_abt_calc.py` из каталога `services/payroll`.
